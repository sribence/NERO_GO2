# Ismert hibák és buktatók — drágán megszerzett tudás

| Tünet | Ok | Javítás |
|---|---|---|
| Router DHCP kliens-listáján nem jelenik meg a robot | A robot statikus IP-t használt, nem kért DHCP-t | Direkt Ethernet-kábel + statikus IP a laptopon, lásd [00-hozzaferes.md](00-hozzaferes.md) |
| `ping` időtúllépés, de van ARP-bejegyzés a MAC-re | Elavult/cache-elt ARP, a gép ténylegesen nem volt fent | Várj / friss ARP-lekérdezés |
| `RTNETLINK answers: File exists` `dhclient` közben | Már volt route/IP az interfészen | Nem feltétlen fatális, folytatható |
| USB-ről bedugva semmi (LED sem) | Jetson USB-C = adatport, nem táp | 19V barrel jack vagy battery kell |
| `apt install` DNS hibák (`Temporary failure resolving`) | Nincs internet-route a roboton | Gateway a laptopra állítva, lásd [00-hozzaferes.md](00-hozzaferes.md) |
| `apt install` HTTPS cert hiba (`chain uses not yet valid certificate`) | A robot órája 1970-re állt vissza áramkimaradás után (nincs RTC-elem/lemerült) | `sudo date -u -s "$(date -u +'%Y-%m-%d %H:%M:%S')"` + `sudo timedatectl set-ntp true`, tartósan: `fake-hwclock` csomag telepítve — automatikus |
| `sudo apt install` "Could not get lock /var/lib/dpkg/lock-frontend" | Az `aptd` daemon befagyva tartotta a zárat egy korábbi automatikus frissítés-ellenőrzés után | `sudo kill <aptd_pid>` — NEM a `packagekit` service, az másik daemon |
| Bash script `-m scriptfile`-lal futtatva 0 kimenettel, exit 128-cal hal el | `plink -m` a teljes szkriptet egyetlen `bash -c "..."` argumentumként adja át — a sortörések szóközzé válnak. Ha van benne `pkill -f <minta>`, és a minta szó szerint szerepel a szkript szövegében is, a `pkill` saját magát a futó shellt is kilövi | Pontosíts (`pkill -x`, teljes bináris útvonal), vagy hagyd ki, ha biztos, hogy még nem fut |
| Háttérbe indított folyamat (`nohup cmd &`) után a szkript "beragad", nincs kimenet | A háttérfolyamat stdin-je nem volt leválasztva az SSH-csatornától, a session nem zárt le | Mindig `nohup cmd < /dev/null > log 2>&1 &` mintával indíts háttérfolyamatot SSH-n át |
| `/camera/toggle_ir` service hívás után a kamera-node lefagy/összeomlik, utána semmilyen kamera-stream nem indul újra normál relaunch-csal sem | Az `astra_camera` driver `glog FATAL` hibával (`Check failed: stream_video_mode_.count(stream_index)`) leáll IR élő bekapcsolásakor, és a fizikai USB-eszköz beragad rossz állapotban (az Orbbec SDK nem zárta le rendesen) | Sima `pkill` NEM elég. `pkill -9 -f astra_camera_node`, várj pár mp-et, majd USB-szintű reset: `python3 -c "import fcntl; fcntl.ioctl(open('/dev/bus/usb/BBB/DDD','wb',buffering=0), 21780, 0)"` (a BBB/DDD a `readlink -f /dev/astra_s` kimenetéből), utána relaunch. **A generált/futtatott kód soha ne hívja élőben az IR-kapcsolót.** |
| `rosrun tf tf_echo laser camera_depth_optical_frame` azt mondja a `laser` frame nem létezik | A LiDAR node csak a `/scan`-t publikálja, a `laser` frame-et semmi nem köti be a TF-fába, amíg nem fut a `robot_model_visualization.launch` (URDF + `robot_state_publisher`) | `roslaunch turn_on_wheeltec_robot robot_model_visualization.launch car_mode:=mini_mec_moveit_four` |
| `ROSLIB.TFClient` a böngészőben sosem kap transzformációt, pedig a `tf_echo` a roboton működik | A roslibjs `TFClient` alapból csak a `/tf` topicot hallgatja; a robot statikus geometriája (`robot_state_publisher`-ből) `/tf_static`-on megy, amit a TFClient nem dolgoz fel | Fix mechanikai kapcsolatoknál (pl. LiDAR↔kamera szerelés) egyszerűbb és megbízhatóbb a mért transzformációt egyszer lekérdezni (`tf_echo`) és beégetni a kliens kódba |
| `web_video_server` `cv_bridge exception: [16UC1] is not a color format` | A 16-bites nyers mélységkép nem alakítható automatikusan színes MJPEG-gé | Saját canvas-renderelés a kliens oldalon, lásd [05-sajat-projekt-iranyitopult.md](05-sajat-projekt-iranyitopult.md) |
| `new Uint8Array(msg.data)` a böngészőben csendben 0 pontot ad a point cloudból | A rosbridge a bájttömb mezőket (`PointCloud2.data`, `Image.data`) Base64-stringként küldi, nem JSON szám-tömbként | `atob()`-bal dekódolni, utána `Uint8Array` |
